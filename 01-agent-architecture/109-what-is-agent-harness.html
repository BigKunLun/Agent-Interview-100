中级 · Agent 架构 · 可交互讲解

模型之外的一切，
才是 Harness。

Agent Harness 是围绕固定 LLM 装配好的运行壳：默认 system prompt、工具注册表、上下文工程、Hook 生命周期、沙箱与权限整套打包。Framework 给你积木，Runtime 保证跑得稳，Harness 直接给你一辆装配好的车。

关键边界：三层不是同义词。Framework 不提供 opinionated 默认 Agent；Runtime 只管持久化执行；Harness 是拿来就能跑、只留少数扩展点的代码 Agent 运行壳。

一 · 三层抽象

积木、稳定器、
装配好的车。

LangChain 官方在 2025-10 把 Agent 软件栈分成三层。自下而上是 LLM → Framework → Runtime → Harness：越往上，封装越多，你拥有的自由度越少。

01 · 最底层可编程抽象

Framework

教你如何拼装 Agent。提供 Agent、Tool、Chain、Handoff 等原语，不提供默认的 prompt、工具集和沙箱。

  • 代表：LangChain / CrewAI / OpenAI Agents SDK
  • 输出：SDK 代码
  • 你要写：loop、memory、hook、sandbox

不负责：给你一个开箱就有性格、能直接跑的 Agent。

02 · 执行稳定性

Runtime

让 Agent 拼好后跑得稳。负责 durable execution、streaming、HITL、跨线程状态，让长任务可恢复、可观察。

  • 代表：LangGraph / Temporal / Inngest
  • 输出：可恢复的执行图或工作流
  • 你要写：图结构、节点逻辑、状态契约

不负责：替你决定 Agent 的性格、默认工具和上下文策略。

03 · 产品形态

Harness

直接给你一辆装配好的车。opinionated defaults 把 prompt、tools、context、sandbox 全部装好，只留少数扩展点。

  • 代表：Claude Code / Codex CLI / Cline / Devin
  • 输出：CLI / IDE 扩展
  • 你只 customize 四件事：system prompt、tools、context、subagents

不负责：像 Framework 一样让你从零定义整个运行时。

一句话区分

Framework 教你“如何拼装 Agent”；Runtime 让你“Agent 拼装好后跑得稳”；Harness 直接给你“拼装好且调好性格的 Agent”。

二 · 最小完整抽象

六个模块，
加一个观测面。

社区收敛出的 Harness 通用抽象是 6+1：Loop、State / Context、Tool、Memory、Hook、Skill，加 Observability。Claude Code 是这套抽象的一个具体实现。

关键判断

MCP 不是 Harness 的核心抽象，它是 Tool 层的一个实现选项；Slash Command 也不是，它是 Skill 的简化形式。Harness 设计要回答的本质问题是：用户能扩展什么、不能扩展什么？

三 · 为什么自研

不是模型不行，
是装配方式不同。

Devin、Claude Code、Codex、Cline 这些 SOTA 代码 Agent 全部自研 harness，不是偶然。原文给了四个硬约束，以及 Terminal Bench 2.0 上的排名差异。

Parallel.ai 的原文数据点称 harness 大约决定 Agent 70% 的实战表现。这是原文引用的经验数据，本页未复现实验，也不把它当作精确定律。

Post-training Coupling

Codex 模型在 post-training 阶段被绑定到 apply_patch 的语法。换 harness 时若不模仿原工具签名，模型能力会掉。模型对工具签名的偏好会被冻进权重。

延迟敏感

ReAct 每步开销 < 100ms 是原文给出的体验底线。多一层 state graph 序列化、checkpointer 写盘和 event bus，对话感会变卡。

Hook / Sandbox 不可让渡

生产 Agent 要拦截 rm -rf、git push --force，还要隔离 apply_patch 避免污染主机。这两类能力必须开箱即用。

Trace 数据是核心 IP

Harness 厂商用 trace 数据 fine-tune 自家模型，形成“模型与 harness 协同进化”的飞轮，不愿意走第三方框架把数据让出去。

2026-09 的第三个选项：厂商托管 Harness

OpenAI 在 2026-09-10 发布 Agents API，把驱动 Codex 的 harness 以托管云服务形式开放，包含编排、长会话和工具调用。Harness 层因此从“自己装配 / 套用现成产品”延伸出第三条路：直接用厂商托管的 harness 基建。对照之下，Claude Agent SDK 走的是“harness 砖块 + 自装配”路线。选型问题从“造还是套”变成“造、套、还是托管”。

四 · 对照与选型

自由与责任，
约束与默认值。

Framework 给自由和责任，Harness 给约束和默认值。选哪层，取决于你要造的是通用编排、领域 Agent，还是一辆能直接上路的代码 Agent。

核心洞察

Framework 让你“造 Agent”；Harness 让你“开 Agent”。Harness 的 opinionated default 反过来是约束，但也是让你少写大量基建代码的捷径。

六 · 2026 前沿

Harness 本身，
成为优化对象。

2026-08 出现的一批工作不再只由人设计 harness，而是把它当作可搜索、可演化、甚至可在线训练的对象。原文明确标注：以下均为社区单次实验，尚无独立复现。

引用限定

以下结论按原文版本保留，均为社区单次实验、未经独立复现。本页没有联网核验论文，也不把单次实验当作生产结论。

StateM（arXiv 2608.15089，2026-08-15）提出 harness scaling：不动模型权重，只把模型外面的运行时做厚——持久状态、阶段局部上下文、受检状态转移、可恢复 runbook、带版本的过程性实践。原文称 Terminal-Bench 2.1 上同一个 GPT-5.5 xhigh 从 83.1% 提升到 92.1%，论文标题最好成绩 95.3%。模型是常量，涨的分全部来自 harness。

方法侧两条路线：DarwinX（arXiv 2608.07545）冻结权重，只演化 prompt / 工具 / 技能 / 控制流，适应度由 benchmark 自带 verifier 给出，不需要标准答案，并用 preserve-and-extend 契约拒绝导致回归的变体；AutoDesign（arXiv 2608.13560）让 meta-optimizer 指导 code agent 按 rollout 反馈递归改写自身 harness。共同点：把工程师从 harness 调参循环里换出去。

手工设计 harness 与自动搜索 / 演化 harness 的对比
维度手工设计 harness（当前主流）自动搜索 / 演化 harness（研究阶段）
谁来改人：读 trace、改 prompt、加工具演化循环 / meta-optimizer 按 rollout 反馈自动改写
优化信号工程师判断 + 离线跑分benchmark 自带 verifier 的通过 / 失败信号，不需标准答案
防退步机制人工回归测试 + code reviewpreserve-and-extend 契约：导致回归的变体直接拒绝
可解释性高，改动都是人写的低，搜出来的 harness 未必讲得清为什么有效
成熟度生产在跑（Claude Code / Codex / Cline）论文阶段，单次实验、未经复现

短期内生产系统仍是手工设计的天下——可解释性和可回滚性不可让渡。但 StateM 的 9 个百分点说明这层还有大量未被人工榨干的空间。

常见误区 / 面试追问

先把边界
说清楚。

三条误区针对三层概念本身，五条追问覆盖 SDK、榜单数据、Runtime 独立化与自动搜索 harness。

误区 1

“Harness 就是另一种框架。”

表面上都是“模型外面的代码”，但本质不同。Framework 是 unopinionated 积木箱，需要你自己拼装 loop / memory / hook；Harness 是 opinionated 装配好的车，这些全部内置，你只能在预留扩展点（CLAUDE.md / Hook / Skill / Subagent）做定制。Framework 给自由 + 责任，Harness 给约束 + 默认值。

误区 2

“自研 Harness 是过度设计，直接用 LangGraph 就行。”

对一般业务系统确实是过度设计。但对需要 opinionated default + post-training coupling 的代码 Agent / 通用电脑 Agent，框架抽象层会成为天花板。Devin / Claude Code / Codex / Cline 全部自研 harness 不是偶然。

误区 3

“换模型不需要换 harness。”

Post-training coupling 让模型与 harness 深度绑定。Codex 模型脱离 apply_patch 签名性能会掉；Claude Sonnet 在 Claude Code 与通用 chat 中表现像两个性格。模型与 harness 是一对深度耦合的系统。

追问 1

LangChain / OpenAI Agents SDK 算 Framework 还是 Harness？

都是 Framework，LangChain 自家文档明确。判断标准：是否给出 opinionated 默认 prompt + tool + sandbox + hook 全套？是否拿来就能跑出一个“有性格的 Agent”？LangChain / Agents SDK 不给默认 prompt 与默认 tool。DeepAgents（LangChain 2025-11 推出的 harness）才算 Harness。

追问 2

Harness 与 SDK 是什么关系？

SDK 是“客户端库”概念（OpenAI Agents SDK、Claude Agent SDK），描述如何调用 API 的 Python / TS 类库；Harness 是“应用形态”概念，描述装配好的 Agent 产品。Claude Code = harness，底层用 Claude Agent SDK；Cursor = harness，底层有自家 Composer SDK。SDK 是 harness 的实现砖块之一。

追问 3

“Harness > 模型”的杠杆数据出自哪里？怎么验证？

出自原文引用的 Terminal Bench 2.0（2026-Q1）：同一个 Claude Opus 4.6 在不同 harness 中差 28 个排名位次。原文建议参考 Artificial Analysis 的 Coding Agents Leaderboard 持续追踪。机制是 system prompt + tool 选择 + context 工程 + retry 策略 + sandbox 隔离五者协同，对单步 ReAct 正确率有乘法效应。这些数字本页未联网复核。

追问 4

Cline SDK 2026-05 为什么把 runtime 从 IDE 剥离？意味着什么？

意味着 Harness 进入“runtime 独立化”阶段。@cline/sdk 把 agent loop 从 VS Code 插件里彻底拆出，可在 CLI / Web / CI 任意 surface 调用。行业方向是：Harness 从“单一产品形态”演化为“runtime + 多 surface 适配器”，同一份 agent runtime 跑 IDE、终端、CI、Kanban。

追问 5

harness 既然决定七成表现，能不能自动搜出最优 harness？

原文的答法是“路径已经跑通，但离生产还有距离”。方法侧：DarwinX 冻结权重只演化 prompt / 工具 / 技能 / 控制流，用 benchmark verifier 当适应度；AutoDesign 让 meta-optimizer 递归改写自身 harness。效果侧：StateM 把 GPT-5.5 xhigh 从 83.1% 推到 92.1%。必须补限定：都是社区单次实验、尚无独立复现；自动搜出的 harness 可解释性差、难回滚，生产环境短期内仍以手工设计为主。
