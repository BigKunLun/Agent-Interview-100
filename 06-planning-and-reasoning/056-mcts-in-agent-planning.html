高级 · Planning & Reasoning · 可交互讲解

先向前模拟，
再决定走哪一步。

MCTS 在决策树上反复做四件事：按 UCB1 选择、扩展候选、评估价值、把结果回传。它用多次浅评估换一个更稳的选择，弥补 LLM 一次生成不能回溯的短板。

关键边界：MCTS 是近似搜索，不保证最优。原文 LATS 用 LLM 同时做动作生成、环境模拟、价值评估和反思，HumanEval 报告 94.4%（GPT-4）。这些是原文版本、未联网核实，不是本页实测。

一 · 四步循环

每一轮，
都回到选择。

MCTS 把决策表示成一棵树：节点是状态，边是动作。它不靠一次生成定输赢，而是把有限的预算分给更有希望的路径。

一轮迭代包含四步，走完第四步就回到第一步，直到预算用完。四个步骤的顺序固定，区别只在每一轮选中哪个节点。

四步里，谁在做事

MCTS 四步在经典算法和原文 LLM 实现中的分工
步骤经典 MCTS原文的 LLM 实现
选择按 UCB1 从根走到叶节点。同一套 UCB1；LLM 不参与选择。
扩展枚举或采样合法动作。LLM 生成 3 个可能的下一步行动。
模拟随机走子到终局，得到回报。LLM 直接评估当前路径达到目标的概率，输出 0–1。
回传更新路径上节点的访问次数和价值。同一套统计更新；LATS 还会调用环境 step 得到观察。

关键区别

原文的“模拟”不是 AlphaGo 式的随机走子，而是一次 LLM 价值评估。这让 MCTS 能用在没有模拟器的任务上，代价是每一步都要花模型调用，而且评估本身可能不准。

UCB1：利用与探索的折中

选择步骤用 UCB1 给每个子节点打分。分数由两部分相加：Q 是平均价值，负责利用；探索项 随访问次数下降，负责给访问少的节点机会。

UCB1 · 原文公式

UCB1 = Q + c × √(ln N / n)

Q = 节点的平均价值（value / visits）
N = 父节点的访问次数
n = 当前子节点的访问次数
c = 探索权重，原文代码默认 1.414

原文代码对未访问节点直接返回无穷大，所以每个候选至少会被评估一次。之后 Q 高的节点被反复利用，访问少的节点靠探索项重新获得机会。

二 · LLM Agent 中的实现

LLM 负责生成，
统计负责选择。

原文的 LLM_MCTS 把扩展和评估交给模型，把选择与回传统一交给 UCB1 统计。LATS 在此基础上加入环境交互和自我反思。

一次迭代的骨架

搜索循环很短：选中节点、扩展、评估、回传。迭代次数用完以后，返回访问次数最多的子节点，而不是单次评分最高的节点。

原文 search 方法节选

for _ in range(self.num_iterations):
    node = self.select(root)              # 1. 选择
    child = await self.expand(node)       # 2. 扩展
    value = await self.simulate(child)    # 3. 模拟
    self.backpropagate(child, value)      # 4. 反向传播

return max(root.children, key=lambda c: c.visits)

原文默认 num_iterations=50。扩展时让 LLM 生成 3 个候选动作；模拟时让 LLM 给当前路径打 0–1 分；回传把同一个价值累加到路径上每个节点。

UCB1 实现 · 原文代码

def ucb1(self, exploration_weight=1.414):
    """UCB1：平衡探索与利用"""
    if self.visits == 0:
        return float('inf')  # 未访问的节点优先
    exploitation = self.value / self.visits
    exploration = exploration_weight * math.sqrt(
        math.log(self.parent.visits) / self.visits
    )
    return exploitation + exploration

注意 math.log(self.parent.visits)：探索项会随父节点总访问量缓慢增长。父节点被访问得越多，所有子节点的探索项都会变大，搜索更愿意试新分支；单个子节点自己访问得越多，它的探索项反而越小。

展开原文 MCTSNode 与 LLM_MCTS 完整代码 
import math

class MCTSNode:
    def __init__(self, state, parent=None):
        self.state = state          # 当前推理状态
        self.parent = parent
        self.children = []
        self.visits = 0
        self.value = 0.0

    def ucb1(self, exploration_weight=1.414):
        """UCB1：平衡探索与利用"""
        if self.visits == 0:
            return float('inf')  # 未访问的节点优先
        exploitation = self.value / self.visits
        exploration = exploration_weight * math.sqrt(
            math.log(self.parent.visits) / self.visits
        )
        return exploitation + exploration

class LLM_MCTS:
    """将 MCTS 与 LLM 结合的规划器"""

    def __init__(self, llm, num_iterations=50):
        self.llm = llm
        self.num_iterations = num_iterations

    async def search(self, problem):
        root = MCTSNode(state=problem)

        for _ in range(self.num_iterations):
            # 1. 选择：沿 UCB1 最高的路径向下
            node = self.select(root)

            # 2. 扩展：用 LLM 生成可能的下一步
            child = await self.expand(node)

            # 3. 模拟：用 LLM 评估这条路径的价值
            value = await self.simulate(child)

            # 4. 反向传播：更新路径上的统计值
            self.backpropagate(child, value)

        # 返回访问次数最多的子节点（最稳健的选择）
        return max(root.children, key=lambda c: c.visits)

    def select(self, node):
        while node.children:
            node = max(node.children, key=lambda c: c.ucb1())
        return node

    async def expand(self, node):
        """用 LLM 生成多个候选动作"""
        actions = await self.llm.invoke(f"""
        当前状态：{node.state}
        请生成 3 个可能的下一步行动。
        """)
        for action in actions:
            child = MCTSNode(
                state=self.apply_action(node.state, action),
                parent=node
            )
            node.children.append(child)
        return node.children[0]  # 返回第一个新节点用于模拟

    async def simulate(self, node):
        """用 LLM 评估当前路径的价值（0-1）"""
        evaluation = await self.llm.invoke(f"""
        评估以下推理路径达到最终目标的可能性（0-1分）：
        路径：{self.get_path(node)}
        目标：{self.goal}
        """)
        return float(evaluation)

    def backpropagate(self, node, value):
        while node:
            node.visits += 1
            node.value += value
            node = node.parent

LATS：让 LLM 同时扮演四个角色

LATS（Language Agent Tree Search，ICML 2024）把 MCTS 用到 LLM Agent 上。同一个 LLM 同时承担四个角色：

LATS 中 LLM 承担的四个角色
角色做什么对应 MCTS 步骤
Action Generator生成候选动作。扩展
Environment Simulator执行动作，得到观察结果。扩展 / 模拟
Value Function评估状态价值。模拟
Self-Reflection失败后总结原因，反思结果影响后续搜索。额外机制，贯穿搜索

Self-Reflection 是 LATS 的核心创新。节点到达终止失败时，模型反思失败原因，并把反思存下来指导后续搜索。原文明确提醒：它不是“额外装饰”，而是搜索的一部分。

原文代码里 LATS 的示例配置是 n_samples=5、depth=7。这两个是示例参数，不代表所有任务的推荐值。

展开原文 LATS 代码 
class LATS:
    """Language Agent Tree Search (ICML 2024)"""

    def __init__(self, llm, environment, n_samples=5, depth=7):
        self.llm = llm
        self.env = environment
        self.n_samples = n_samples
        self.depth = depth

    async def solve(self, task):
        root = LATSNode(observation=task)

        for iteration in range(self.n_samples):
            node = self.select(root)

            # LATS 的关键创新：LLM 同时充当多个角色（决策、生成、评估、反思）
            # Self-Reflection 是 LATS 的核心创新之一，不应视为"额外"

            # 角色 1：Action Generator（生成候选动作）
            actions = await self.generate_actions(node)

            # 角色 2：Environment Simulator（模拟执行结果）
            for action in actions:
                observation = await self.env.step(action)
                child = LATSNode(observation=observation, action=action)
                node.add_child(child)

            # 角色 3：Value Function（评估状态价值）
            for child in node.children:
                value = await self.evaluate_state(child)
                child.value = value

            # 角色 4：Self-Reflection（核心创新——从失败中学习并指导后续搜索）
            if self.is_terminal_failure(node):
                reflection = await self.reflect_on_failure(node)
                # 反思被存储，影响后续搜索
                self.reflections.append(reflection)

            self.backpropagate(node)

        return self.get_best_trajectory(root)

MCTS 与其他搜索策略

Greedy、BFS、DFS 与 MCTS 四种搜索策略的对比
策略搜索方式优势劣势LLM 调用
Greedy (CoT)单路径，无回溯最快、最便宜容易卡在局部最优1 次
BFS (ToT)逐层扩展所有候选保证找到最浅的解内存消耗大，不适合深搜索O(b^d)
DFS (ToT)深入一条路，失败回溯内存高效可能陷入无解的深分支O(b*d)
MCTS (LATS)UCB1 引导的自适应搜索探索-利用平衡，渐进最优需要大量迭代，成本最高O(N*b)，N=迭代次数

这里的 b 是分支因子，d 是深度，N 是迭代次数。MCTS 不把预算平均分给所有分支，而是根据已看到的回报动态分配，这是它和 BFS/DFS 的主要区别。

LATS 与 Reflexion 的区别

Reflexion 是线性的：失败一次，写反思，再从头试一次。LATS 是树形的：它保留多条候选路径，用反思信息影响搜索，并在树里回溯。LATS 包含反思能力，但搜索策略更系统。

四 · 成本与适用场景

先算调用账，
再决定搜不搜。

MCTS 的每一轮迭代都要多次调用模型：生成动作、评估价值，LATS 还要执行环境动作。它适合高价值、能容忍延迟的任务，不适合实时对话。

五种降本手段

原文列出的五种 MCTS 成本控制手段
手段原文做法代价
减少迭代次数从 50 降到 10–20。牺牲少量质量，换取大幅降本。
缩小分支因子每步生成 2–3 个候选，而非 5–10 个。候选变少，可能漏掉好路径。
用小模型做模拟扩展用大模型，评估用小模型。评估准确性下降。
早期终止找到足够好的方案就停止。放弃追求最优。
缓存重复状态相同状态不重复评估。需要状态归一化和缓存管理。

什么时候值得用

  • 适合：高价值任务，例如代码生成、复杂分析、需要比较多条方案的规划；这些任务允许较高延迟，也愿意为成功率付费。
  • 不适合：实时对话、低延迟 API、简单事实查询；这些场景用 CoT 或单次 ReAct 更划算。
  • 生产折中：多数团队用简化版，减少迭代次数、缩小搜索空间，只在关键决策点做树搜索。

面试时可讲的一句话

MCTS 买的是“多试几条路再决定”，不是“一定找到最优”。如果任务错一次代价很高、又等得起，这笔调用账通常划算；如果用户等不起，搜索越完整越拖累体验。

常见误区 / 面试追问

四个容易被
追问的点。

前两条是误区，后两条是面试追问；答案都来自原文。

误区 1

“MCTS 只适合棋类游戏。”

MCTS 是通用搜索框架。LATS 证明它在编程、网页导航、推理等 Agent 任务上都有效。关键是要定义好“状态”“动作”和“价值函数”，而 LLM 可以同时充当这三者。

误区 2

“MCTS 保证找到最优解。”

MCTS 是近似算法，理论上要无限迭代才收敛到最优。实际迭代次数有限，只能找到“足够好”的方案。相比贪心搜索，它通过探索-利用平衡显著降低了陷入局部最优的风险，但这不是保证。

追问 1

“LATS 和 Reflexion 有什么区别？”

Reflexion 从失败中学习并重试，是线性的；LATS 在搜索树中探索多条路径，并用反思信息引导搜索，是树形的。LATS 包含 Reflexion 的自我反思能力，但搜索策略更系统。

追问 2

“MCTS 在生产 Agent 系统中实用吗？”

对高价值、允许高延迟的任务很实用，例如代码生成、复杂分析。对实时对话等低延迟场景，成本太高。生产中常用简化版：减少迭代次数、缩小搜索空间。
