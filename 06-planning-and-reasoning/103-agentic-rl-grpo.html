高级 · Planning & Reasoning · 可交互讲解

奖励看任务完成，
不看回答讨不讨喜。

Agentic-RL 用任务环境的可验证反馈训练工具调用和规划；GRPO 不训练 Critic，而是对同一 prompt 采样一组轨迹，用组内相对排名算 advantage。

边界：GRPO 适合可验证奖励的任务；奖励函数设计是核心难点。原文字段（R1 配置 group_size=64、DAPO 效果、Terminal-Universe 等）按原文标注，属原文版本、未联网核实。

一 · Agentic-RL vs RLHF

奖励来自任务，
不是来自偏好。

两者都用强化学习优化 LLM，但目标不同：RLHF 优化“回答讨不讨喜”，Agentic-RL 优化“任务有没有完成”。

传统 RLHF 与 Agentic-RL 在目标、奖励来源和场景上的对比
维度传统 RLHFAgentic-RL
目标对齐人类偏好（helpful、harmless、honest）。提升任务执行能力（工具调用、规划、推理）。
奖励来源人类标注 → Reward Model 打分。任务环境自动评估（可验证奖励）。
训练信号回答 A 比回答 B 更好。任务是否完成、执行效率、步骤正确性。
典型场景聊天、创意写作、安全对齐。Agent 工具调用、代码生成、多步推理。

RLHF 需要人类标注偏好，训练信号受标注瓶颈限制；Agentic-RL 的奖励可以由环境自动计算，例如代码是否通过测试、答案是否匹配 ground truth，因此可以大规模生成训练信号。

二 · GRPO vs PPO

不用 Critic，
用组内排名。

PPO 要额外训练 Critic 估计状态价值；GRPO 直接对同一 prompt 采样一组响应，用组内相对排名替代 Critic。

PPO · 需要 Critic

  1. Actor 策略网络生成响应。
  2. Critic Model 估计 V(s)。
  3. Advantage = R − V(s)。
  4. PPO Clipping 更新 Actor。

Critic 要单独训练，显存和训练开销都更高；优势估计依赖 Critic 的质量。

GRPO · 无需 Critic

  1. 同一 prompt 采样 G 个响应。
  2. 逐条计算奖励 r1 … rG。
  3. 组内标准化 A = (r − mean) / std。
  4. 带 KL 惩罚更新 Policy。

不需要 Critic；组大小 G 决定相对排名的稳定性，也决定采样成本。

核心公式

组内标准化 · 原文代码

mean = rewards.mean()
std = rewards.std() + 1e-8          # 避免除零
advantages = (rewards - mean) / std # 组内标准化

奖励高于组均值的轨迹得到正 advantage，低于均值的得到负 advantage，接近均值的几乎不动。这样不需要 Critic 也能判断“这条轨迹比同组其他人好多少”。

PPO 与 GRPO 在 Critic、优势计算、采样方式和显存上的对比
维度PPOGRPO
Critic Model需要，额外训练开销大。不需要，原文称节省约 50% 显存。
Advantage 计算A = R − V(s)，依赖 Value Function。A = (r − mean) / std，依赖组内相对排名。
采样方式每个 prompt 1 个响应。每个 prompt G 个响应。
训练稳定性依赖 Critic 质量。依赖组大小 G。
显存占用Actor + Critic。仅 Policy + Ref。
代表应用ChatGPT / InstructGPT。DeepSeek-R1。
适合场景通用 RLHF。可验证奖励的任务。

“节省约 50% 显存”等为原文口径、未联网核实；实际占用随模型、框架和并行策略变化。

展开原文 GRPOTrainer 完整代码 
import torch
import torch.nn.functional as F

class GRPOTrainer:
    """简化版 GRPO 训练循环"""

    def __init__(self, policy_model, ref_model, reward_fn,
                 group_size=8, kl_coeff=0.05, clip_eps=0.2, lr=1e-6):
        self.policy = policy_model       # 当前策略（要训练的 Agent）
        self.ref = ref_model             # 参考策略（SFT 后冻结的模型）
        self.reward_fn = reward_fn       # 奖励函数
        self.G = group_size              # 每组采样数量
        self.kl_coeff = kl_coeff         # KL 散度惩罚系数
        self.clip_eps = clip_eps         # PPO-style 裁剪范围
        self.optimizer = torch.optim.Adam(self.policy.parameters(), lr=lr)

    def compute_group_advantage(self, rewards: torch.Tensor) -> torch.Tensor:
        """
        GRPO 的核心：组内相对排名计算 advantage
        不需要 Critic Model，直接用组内统计量归一化
        """
        # rewards: shape (G,)，G 个响应的奖励值
        mean = rewards.mean()
        std = rewards.std() + 1e-8   # 避免除零
        advantages = (rewards - mean) / std  # 组内标准化
        return advantages

    def grpo_loss(self, prompt_tokens, response_tokens_group,
                  advantages, old_logprobs):
        """
        计算 GRPO 策略梯度损失
        """
        total_loss = 0.0
        for i in range(self.G):
            # 计算当前策略下的 log 概率
            new_logprob = self.policy.log_prob(
                prompt_tokens, response_tokens_group[i]
            )
            # 计算参考策略下的 log 概率（用于 KL 惩罚）
            with torch.no_grad():
                ref_logprob = self.ref.log_prob(
                    prompt_tokens, response_tokens_group[i]
                )

            # 重要性采样比率
            ratio = torch.exp(new_logprob - old_logprobs[i])

            # PPO-style 裁剪
            clipped_ratio = torch.clamp(ratio, 1 - self.clip_eps, 1 + self.clip_eps)
            policy_loss = -torch.min(
                ratio * advantages[i],
                clipped_ratio * advantages[i]
            )

            # KL 散度惩罚（K3 unbiased estimator）：防止策略偏离参考模型太远
            # 原论文 DeepSeekMath (arXiv:2402.03300) 使用的是 K3 无偏估计：
            #   KL ≈ exp(r-n) - (r-n) - 1，其中 r = ref_logprob, n = new_logprob
            # 这个估计始终 ≥ 0，期望值等于真 KL 散度，方差低于线性差分。
            log_ratio = ref_logprob - new_logprob
            kl_penalty = self.kl_coeff * (torch.exp(log_ratio) - log_ratio - 1)

            total_loss += (policy_loss + kl_penalty).mean()

        return total_loss / self.G

    def train_step(self, prompts_batch):
        """单步 GRPO 训练"""
        batch_loss = 0.0

        for prompt in prompts_batch:
            # Step 1: 对同一 prompt 采样 G 个完整轨迹
            responses = []
            old_logprobs = []
            for _ in range(self.G):
                with torch.no_grad():
                    response, logprob = self.policy.sample(prompt)
                    responses.append(response)
                    old_logprobs.append(logprob)

            # Step 2: 计算每个响应的奖励
            rewards = torch.tensor([
                self.reward_fn(prompt, resp) for resp in responses
            ])

            # Step 3: 组内相对排名 → advantage（GRPO 核心）
            advantages = self.compute_group_advantage(rewards)

            # Step 4: 计算 GRPO 损失并更新
            loss = self.grpo_loss(prompt, responses, advantages, old_logprobs)
            batch_loss += loss

        # 反向传播与参数更新
        self.optimizer.zero_grad()
        batch_loss.backward()
        self.optimizer.step()

        return batch_loss.item()

三 · 奖励函数与 R1

奖励写错，
模型就学歪。

Agentic-RL 的核心难点不是算法，是奖励函数。原文把它拆成四个维度，并强调任务完成度必须占主导。

四维奖励函数

原文 compute_agent_reward 代码

def compute_agent_reward(prompt, trajectory, max_steps=20):
    # 维度 1：任务完成度（权重最高，可验证任务直接判正误）
    completion = 1.0 if trajectory.final_answer == get_ground_truth(prompt) \
                 else partial_match_score(trajectory.final_answer, prompt)

    # 维度 2：工具使用准确率（调用了正确的工具和参数）
    tool_calls = trajectory.get_tool_calls()
    tool_acc = sum(tc.is_valid() for tc in tool_calls) / max(len(tool_calls), 1)

    # 维度 3：步骤简洁性（用更少步骤完成 → 更高奖励）
    efficiency = max(0, 1.0 - len(trajectory.steps) / max_steps)

    # 维度 4：格式遵循度（输出符合 JSON / 函数调用格式等）
    format_score = max(0, 1.0 - 0.2 * trajectory.count_format_violations())

    # 加权求和——任务完成度占主导，避免 reward hacking
    return 0.50 * completion + 0.20 * tool_acc + 0.15 * efficiency + 0.15 * format_score

原文的权重是 50% / 20% / 15% / 15%。任务完成度占一半以上，是为了避免模型学会“格式正确但不解决问题”的 reward hacking。

设计陷阱

效率分只看步骤数：1 − 步数 / 20。一条什么都没做的轨迹，步数为 0，效率反而拿满分。所以完成度和工具准确必须占足够权重，否则模型会学会“少做事、拿格式分”。

DeepSeek-R1 的训练范式

原文把 R1 的训练拆成五步：基座 DeepSeek-V3（671B MoE）→ Cold Start SFT（数千条高质量长 CoT，教模型开始思考）→ 大规模 GRPO（核心）→ Rejection Sampling + SFT（蒸馏 RL 策略）→ 第二轮 RL（加入 helpfulness / safety 奖励）。

RL 中涌现的行为

  • 自发长思考链：模型自主生成数千 token 的推理过程。
  • Aha moment：模型学会说 “Wait, let me reconsider...” 并自我纠错。
  • 多角度验证：用不同方法交叉检验同一结论。
  • 思考时间自适应：简单题想得少，难题想得多。

原文强调这些行为没有人工逐步示范，是 RL 训练中自发出现的。

环境供给：Agentic-RL 的现实瓶颈

原文 2026-09 口径、未联网核实

Terminal-Universe（arXiv 2609.04148，原文称 224 upvotes）代表“环境生成”路线：把已经积累的终端 agent 轨迹反向转化为可反复执行、自带可验证任务的环境，缓解后训练环境稀缺。这是原文对 2026 年趋势的判断，本页未核验论文。

四 · GRPO 之后

论文版 GRPO，
只是起点。

2025 年起出现一批 GRPO 改良算法，主要解决长轨迹、稀疏奖励和训练稳定性。原文的判断是：2026 工业界很少直接跑 paper-version GRPO。

DAPO、GSPO、REINFORCE++/RLOO 和其他 GRPO 改良方向的对比
算法 / 方向改进点原文备注
DAPO（ByteDance，2025）Clip-Higher 放宽正向 ratio 上界；Dynamic Sampling 剔除全对/全错样本；Token-level loss；Overlong-shaping 软惩罚长输出。原文称 AIME 2024 用 Qwen2.5-32B 在 50% steps 内超过 R1-Zero；公开了完整训练栈。
GSPO（Qwen Team，2025）把 ratio / clipping 从 token 级别上升到 sequence 级别，解决长 CoT 训练不稳。用于 Qwen3 系列推理模型训练。
REINFORCE++ / RLOO 改进把 GRPO 退化为更简单的 REINFORCE + baseline 估计。RLOO 用 Removed-One-Out baseline；Reinforce++ 来自 NousResearch。
VAPO / Loop-GRPO / DR-GRPOValue-augmented、loop-aware、debiased GRPO 等支线。原文共识：GRPO 是 2025 后训练的事实基线，但要针对任务大量改良。

从 RLHF 到 Agentic-RL

RLHF（2022–2023）人类偏好对齐，关注对话质量；代表：ChatGPT；算法：PPO。
→
RLAIF（2023–2024）AI 反馈对齐，规模化标注；代表：Claude；算法：PPO / DPO。
→
Agentic-RL（2024–2025+）任务环境反馈，训练工具调用和规划；代表：DeepSeek-R1；算法：GRPO / REINFORCE。

目标从“回答让人满意”转向“任务真的完成”，奖励从人类标注转向环境验证，算法从 PPO 转向更适合可验证奖励的 GRPO 系列。

常见误区 / 面试追问

两个误区，
两个追问。

前两条是误区，后两条是面试追问；答案都来自原文。

误区 1

“RLHF 和 Agentic-RL 是一回事。”

两者都用强化学习优化 LLM，但目标不同。RLHF 优化人类偏好，依赖人类标注训练 Reward Model；Agentic-RL 优化任务执行能力，奖励来自环境的可验证反馈，例如代码是否通过测试、答案是否正确。后者可以大规模自动化生成训练信号。

误区 2

“RL 训练 Agent 不需要 SFT 冷启动。”

DeepSeek 的 R1-Zero 表明，纯 RL 虽能涌现推理能力，但有两个问题：输出可读性差，常混合多种语言；训练初期探索效率极低，模型可能长时间在无意义行为里徘徊。Cold Start SFT 用少量高质量数据给模型一个起跑点，显著提升训练效率和最终输出质量。

追问 1

“如何设计 Agent 任务的奖励函数？”

核心原则是可验证加多维度。可验证任务直接用答案正确性作主奖励；不可验证任务用 LLM-as-Judge 或人类评估。除了完成度，还应奖励工具使用准确性、执行效率和格式规范性。权重上任务完成度应占 50% 以上，避免模型学会“格式正确但不解决问题”的 reward hacking。

追问 2

“Agentic-RL 的训练数据如何采集？”

分阶段。SFT 阶段需要少量高质量 Agent 轨迹，通常几千到几万条，来自专家标注或强模型生成。RL 阶段的数据可以自动生成：设定任务 prompt，Agent 自由探索，环境自动打分。关键挑战是任务分布多样性，否则模型只在训练分布内表现好；实践中常用课程学习，从简单任务逐步增加难度。
