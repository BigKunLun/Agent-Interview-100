推理能力，
成了旗舰的开关。

2026 年的变化不是又出了一个推理模型，而是三家旗舰都把 thinking 做成了内置可调模式。选型问题从“用不用推理模型”变成“这个任务开不开 thinking、给多大预算”。

    一 · 推理与通用合流

    专用推理模型，
    边界正在消失。

    2024–2025 年，o1/o3、DeepSeek-R1 是独立推理品类，GPT-4o、Claude Sonnet 3.5 是通用模型。到 2026，三家旗舰都把推理做成内置可调模式。

    2024-2025 旧版图与 2026 新图景的对比
    阶段形态选型问题
    2024–2025专用推理模型与通用模型分开：推理模型贵、慢、难题强；通用模型快、便宜、难题弱。该不该用推理模型？
    2026旗舰通用模型 = 通用能力 + 可调 thinking 模式；简单任务关，复杂推理开。这个任务该不该开 thinking、开多大 budget？
    OpenAI

    thinking 显式开关

    用户在请求里决定开或关，按任务调节 reasoning effort。

    Anthropic

    extended thinking

    用 budget_tokens 控制思考深度；interleaved thinking 让思考与工具调用交错。

    Google

    Deep Think + Thought Signatures

    Deep Think 负责深度推理，Thought Signatures 让 agent 追踪自身推理过程。

    驱动合流的力量有两个。第一，Test-Time Compute Scaling 被验证有效：让模型多想一会儿的收益，比单纯堆参数更划算。第二，Agent 场景要求“会推理也会调工具”：纯推理模型不擅工具交错，而 agent 需要思考、调工具、再思考的循环。

    所以旧问题被替换了：从“该不该用推理模型”，变成“这个任务该不该开 thinking、开多大 budget”。

    三 · 选型、预算与成本

    先问任务，
    再问开不开 thinking。

    合流之后，决策不再是选模型品类，而是选“档位 + thinking 开关 + 预算”。原文给了四条判断规则和一张路由图。

    四条选型规则

    原文 choose_model_and_thinking 伪代码节选

    # 规则 1：实时对话、翻译、简单 QA → 关 thinking，用通用档
if complexity == "simple" or latency_sensitive:
    return {"thinking": False, "tier": "standard"}

# 规则 2：数学/算法/科学证明/复杂多步推理 → 开 thinking，给足 budget
if complexity == "complex_reasoning":
    return {"thinking": True, "budget_tokens": 8000}

# 规则 3：Agent 长任务 → 开 interleaved thinking + 工具交错
if needs_tools and task.long_horizon:
    return {"thinking": True, "interleaved": True, "budget_tokens": "per_step"}

# 规则 4：成本敏感的批量 → 关 thinking，用 Sonnet/Flash 档兜底
if cost_sensitive:
    return {"thinking": False, "tier": "mid"}

    这四条不是互斥的硬规则，更像优先级：先看是否实时和简单，再看是否复杂推理，再看是否长任务工具循环，最后用成本约束兜底。原文的 budget_tokens: 8000 是示例值，不是通用推荐。

    Test-Time Compute Scaling

    训练时扩展与测试时扩展的对比
    范式方法代表局限 / 优势
    Train-Time Scaling（旧）加大参数量、堆训练数据。GPT-3 → GPT-4边际收益递减，Scaling Law 放缓。
    Test-Time Scaling（2026 主流）允许模型思考更久，生成更长的推理 token。o1 → o3 → 旗舰通用模型内置 thinking按需分配：简单题少想，难题多想；从固定开关演化为 budget_tokens 可控。

    RL 训练信号方面，可验证奖励（数学、代码可自动判对错）已成共识，偏好和 Judge 奖励作补充；thinking 与工具调用交错，三家都已支持。

    四 · 信任危机与历史脉络

    高分不等于
    生产可靠。

    原文提醒：SWE-bench Verified 顶部分数已经很高，但出现 gaming 信任危机。理解历史脉络，才知道这些能力是怎么来的。

    SWE-bench 的信任危机

    原文数据、未联网核实

    SWE-bench Verified 顶部分数已达 87–94%，原文称 Claude 系列领先；但同时出现“benchmark 可被 gaming”的信任危机。harness 配置、retry 策略、reasoning effort 都会显著影响分数，同一模型换个 harness 排名能差出几十位。

    新基准 SWE-EVO 转向长周期软件演化任务，弥补 SWE-bench 只测单点 bug 修复的局限。对选型的含义：不能只看 SWE-bench 或推理分，要看你自己的 harness 和真实任务分布。

    历史脉络：概念仍然有效，载体变了

    OpenAI o 系列（开启者）o1 / o1-pro：2024-09 / 12，闭源 RL CoT，首次提出 test-time compute scaling。o3 / o3-mini：2025-01，推理加工具调用，ARC-AGI 高计算配置下 87.5%。后续 o3-pro / o4 / GPT-5 系列逐步把推理做成通用模型的可开关模式。
    DeepSeek-R1（开源里程碑）R1-Zero 用纯 GRPO 强化学习，不用 SFT，涌现 “Aha moment”：模型自学会说“等一下，让我重新检查”。R1 用 Cold Start SFT + 大规模 RL，AIME 2024 达 79.8%（满血 671B）。蒸馏到 7B/14B/32B/70B，证明推理能力可以迁移到小模型。
    Anthropic extended thinking起点是 Sonnet 3.7（2025-02），用 budget_tokens 控制思考深度；Sonnet 4/4.5 引入 interleaved thinking；原文称 Sonnet 5 / Opus 4.7 系列继承，长思考链稳定性大幅提升。
    Google Deep ThinkGemini 2.5 Deep Think（2025-08）是 Google 首个公开多 agent 模型，IMO 2025 拿到 Bronze；Gemini 3.x 演化为 Thought Signatures + Agent Mode。

    仍然有效、值得记住的概念：Test-Time Compute Scaling；RL 训练推理能力（GRPO 等可验证奖励算法）；Aha moment、自我纠正、回溯；蒸馏把大模型推理能力迁移到小模型；budget_tokens 从固定开关演化为可控预算；interleaved thinking 让思考与工具调用交错。

    以上日期、分数、排名均为原文 2026-10 口径，未联网核实；本页不更新排名，也不把这些历史结论当作当前生产事实。

    常见误区 / 面试追问

    两个误区，
    五个追问。

    前两条是误区，后五条是面试追问；答案都来自原文。

    误区 1

    “2026 年还该不该选专用推理模型？”

    这个问题本身已经过时。推理能力已合流进通用旗舰，成为可开关的 thinking 模式。正确的问法是：这个任务该不该开 thinking、开多大 budget。o1/o3 那种“独立推理品类”的边界已经模糊，纯专用推理模型的份额在收缩。

    误区 2

    “Agent 选型看 SWE-bench / 推理分就够了。”

    SWE-bench Verified 顶部已达 87–94%，但出现 gaming 信任危机：harness 配置、retry 策略都能显著刷分。选型要看“agentic 能力 × 成本 × harness 耦合度”三维，并在自己的真实任务上验证。

    追问 1

    “Sonnet 5 为什么敢叫‘最 agentic 的 Sonnet’？”

    三条依据：drop-in 替换 Sonnet 4.6，API 兼容；主提升集中在 agentic coding 与自主任务执行；定价 $2 / $10 per MTok，把 agentic 能力做到中端价位，让原本要跑顶级旗舰的工作流可以下放。

    追问 2

    “post-training coupling 对选型意味着什么？”

    模型在 post-training 阶段会把对特定工具签名（apply_patch、某套 MCP 工具）的偏好冻进权重，脱离配套 harness 性能会掉。所以选模型其实在选“模型 + harness”组合：Claude 配 Claude Code、Codex 配 apply_patch、Gemini 配 ADK。

    追问 3

    “Gemini 的 Thought Signatures 和 Claude 的 extended thinking 有什么区别？”

    两者都把推理做成可见、可控的一等公民，但侧重不同。Claude 的 extended thinking 是可配预算的思考链，用 budget_tokens 控制深度，interleaved 与工具交错；Gemini 的 Thought Signatures 强调 agent 对自身推理过程的追踪与可观测，配合 Agent Mode 让 agent 主动写脚本改环境。

    追问 4

    “1M 上下文了，Agent 还需要 RAG 吗？”

    单针检索在 1M token 下对顶级模型已基本解决，但多跳推理超过 256K 后性能显著下降。所以长任务、大知识库仍需 RAG；1M 上下文解决的是“短期工作记忆”，不是“长期知识”。

    追问 5

    “未来 Agent 会全面开 thinking 吗？”

    更可能是混合架构加模型路由：规划和关键判断开 thinking，常规执行关 thinking。thinking token 单独计费，且显著拉高成本与延迟，无脑全开不划算。
