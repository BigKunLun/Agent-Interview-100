一 · 作用与硬约束

索引和查询，
必须同一个模型。

Embedding 模型把文本转成高维向量，让语义相似的文本在向量空间里更近。它在 RAG 里出现两次：索引时把文档块转成向量，查询时把用户问题转成向量。

关键约束

索引和查询必须使用同一个 Embedding 模型。否则向量空间不一致，检索完全失效；换模型时，所有已索引向量都必须重新生成。

这也是为什么“换一个榜单更高的模型”不是零成本操作：模型一换，索引就要重建，成本与数据量成正比。

VOYAGE AI

性价比之王

voyage-3-large 在多项 MTEB 子任务上超越 OpenAI text-embedding-3-large 与 Cohere embed-v3（幅度因数据集而异）。1024 维比 OpenAI 的 3072 维节省约 3 倍存储，价格约为 OpenAI 的一半。

  • 领域模型：voyage-law-3（法律）
  • voyage-code-3（代码）
  • voyage-finance-2（金融，原文称 v3 未发布）

OPENAI

最均衡的默认

原文引用 Agentset 评测，称它在更多直接对比中胜出，是最稳定的生产选择。支持 dimensions 参数把 3072 维缩到 1536 或 256，在精度和存储间权衡。

  • 3072 维：最高精度
  • 1024 / 1536：省存储，轻微精度损失
  • 适合没有强领域偏好的默认场景

COHERE

多语言 / 多模态

MTEB 多语言子任务排名前列，支持 100+ 语言的跨语言检索，能在同一语义空间嵌入文本和图像，支持 128K token 超长输入。

  • 跨语言检索
  • 文本 + 图像
  • 长文档输入
展开原文代码：OpenAI 维度缩减 
from openai import OpenAI
client = OpenAI()

# 全维度：最高精度
full = client.embeddings.create(
    model="text-embedding-3-large",
    input="查询文本"
)  # 3072 维

# 缩减维度：节省存储，轻微精度损失
compact = client.embeddings.create(
    model="text-embedding-3-large",
    input="查询文本",
    dimensions=1024  # 从 3072 缩减到 1024
)

为什么选自托管

数据隐私：文档不发给第三方 API；成本控制：大量数据时自托管更经济；离线部署：无网络环境；完全可控：可以微调和定制。

四 · 微调策略

先测通用模型，
再决定要不要微调。

领域特定微调可带来 10–30% 的检索质量提升，但前提是通用模型确实不满意，且问题出在领域术语或检索逻辑，而不是数据质量。

微调前先算清成本

  1. 必须重新索引：微调改变 Embedding 空间，所有已索引向量都要重新生成。
  2. 数据量要求：至少 1000 个标注样本，理想 5000–10000 个。
  3. 评估闭环：用 Recall@k、MRR 对比微调前后。
  4. 基础模型：选与领域最接近的基础模型，效果更好。

五 · 决策框架

按顺序排除，
最后落到默认。

原文的 choose_embedding_model 先看 MVP，再看多语言、隐私、预算、领域，最后默认 OpenAI text-embedding-3-large。

展开原文决策代码 
def choose_embedding_model(requirements: dict) -> str:
    if requirements["stage"] == "mvp":
        return "all-MiniLM-L6-v2"        # 免费、快、够用

    if requirements["multilingual"]:
        return "cohere-embed-v4"          # 100+ 语言

    if requirements["privacy_critical"]:
        return "bge-m3 (self-hosted)"     # MIT 许可，完全可控

    if requirements["budget"] == "tight":
        return "voyage-3-large"           # 最高性价比

    if requirements["domain_specific"]:
        if requirements["domain"] in ["legal", "code", "finance"]:
            return f"voyage-{domain}-2"   # 领域特化模型
        else:
            return "fine-tune bge-m3"     # 自定义微调

    return "openai-text-embedding-3-large"  # 最均衡的默认选择

原文的一处版本不一致

正文列出的领域模型是 voyage-law-3、voyage-code-3、voyage-finance-2，但决策代码返回 voyage-{domain}-2。两者版本号不一致，本页不替原文做选择；实际选型时以官方文档的当前模型名为准。

常见误区 / 面试追问

MTEB 第一，
不等于你的第一。

两条误区覆盖榜单和维度；两条追问覆盖换模型与 Embedding / LLM 的厂商关系。

误区 1

“选 MTEB 排名第一的就对了。”

MTEB 是通用基准，你的领域数据分布可能完全不同。必须在自己的数据集上评估。

误区 2

“维度越高越好。”

3072 维比 1024 维精度更高，但存储 3 倍、检索更慢。很多场景下 1024 维甚至 768 维就足够。OpenAI 的维度缩减功能正是为此设计。

追问 1

如果换了 Embedding 模型怎么办？

必须重新索引所有文档。索引和查询必须使用完全相同的模型。这是换模型的最大成本。

追问 2

Embedding 和 LLM 需要来自同一家吗？

不需要。Embedding 模型和 LLM 是独立组件。可以用 Voyage 的 Embedding + Anthropic 的 Claude 生成，完全没问题。
