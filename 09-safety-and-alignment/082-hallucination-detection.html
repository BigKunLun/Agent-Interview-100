中级 · Safety & Alignment · 可交互讲解

幻觉的可怕，
是它会被执行。

普通聊天说错一句话，用户还能怀疑。Agent 说错一句话，可能已经调了工具、改了数据、发了请求。检测要抓的不是“语气像不像”，而是每条声明有没有依据。

原文把检测分三类：不确定性估计、知识验证、自我一致性检查。缓解则要分层：结构化约束、RAG 接地、Guardian Agent、人工闭环。本页的损失金额与减少率按原文标注；互动中的公司、数字和 API 都是固定教学数据，不调用模型、不联网。

    一 · 幻觉分三种

    说错、编造、
    误解工具。

    原文把幻觉分成内在、外在，以及 Agent 特有的第三类。第三类最容易被忽略：工具明明返回了正确数据，Agent 在解读时仍能加出原文没有的结论。

    内在幻觉、外在幻觉与 Agent 特有幻觉的类型和示例
    类型定义例子
    内在幻觉生成内容与提供的上下文冲突。文档写“收入增长 10%”，Agent 总结为“收入下降”。
    外在幻觉凭空捏造，无法从输入或已知知识验证。虚构不存在的论文、编造 API 参数。
    工具输出误解Agent 特有的幻觉：工具返回 A，Agent 总结成 B。数据库返回“Q3 收入 1,200 万”，Agent 总结成“Q3 收入增长 20%”。
    跨步骤信息丢失多步推理中遗忘或歪曲之前的结果。第一步查到 A 供应商报价更低，最后汇总时写成 B 更低。
    虚构工具能力声称工具能做它实际做不到的事。看板只有汇总视图，Agent 说“可按地区拆分并导出 CSV”。

    Agent 场景的关键差异

    普通 LLM 的幻觉停在文本层，Agent 的幻觉会进入行动层。它会按编造的 API 参数发请求、按错误的增长率改预算、按不存在的功能给用户承诺。所以“调了工具”不等于“有事实依据”，还要验证 Agent 对工具输出的解读。

    原文给的行业口径是：幻觉相关事故每年造成超过 2.5 亿美元损失。这个数字按原文 2026-10 口径保留，本页未联网核实，也不把它当作精确统计。

    二 · 三类检测

    不确定、不一致、
    对不上外部事实。

    三类方法抓的是不同信号，没有哪一类单独够用。原文还给了一个容易误读的名字：FINCH-ZK 的“零知识”指不依赖外部知识库，不是密码学里的零知识证明。

    检测 1 · 不确定性

    Log Probability 分析

    看 token 的 logprob。原文示例把 logprob < -5.0 的片段标为可疑。它便宜、实时，但只反映模型自己的把握，模型“自信地错”时抓不到。

    检测 2 · 一致性

    多次采样比对

    同一问题采样 N 次，抽取关键声明，看每条声明被多少次回答支持。原文示例用 5 次采样、支持数达到 (N-1)×0.6 才算一致。成本随 N 倍增，且只能发现“不稳定”，不能发现“稳定地错”。

    检测 3 · 外部验证

    知识库 / 搜索交叉验证

    把声明拿去和外部知识库、搜索结果、数据库最终状态比对。它能抓“稳定地错”，但依赖外部源的质量，也有延迟和成本。

    检测 2 的跨模型变体 · FINCH-ZK

    跨模型一致性

    把回答切成语义段落，用多个模型独立生成并比对，不使用外部知识库。原文注明：这里的“零知识”指 zero external knowledge，不是密码学 ZKP；核心是跨模型互验，不是单模型内部一致性。

    三类方法各自漏什么

    三类幻觉检测方法的信号、擅长与盲区
    方法信号擅长抓盲区成本
    Logprobtoken 概率生僻实体、编造参数自信的错误、流畅的编造几乎为零
    多次采样声明支持率不稳定的答案、随机编造稳定复现的错误N 倍生成
    外部验证证据比对事实错误、过期信息外部源本身错误或缺失检索 + 判断延迟
    跨模型互验模型间差异单模型系统性编造多个模型共享同一错误多模型调用

    三 · 缓解策略

    让模型少编，
    也让它编了能被抓住。

    原文给了四条缓解路径，优先级不同：结构化输出最便宜，RAG 最通用，Guardian Agent 最可靠但最贵，人工闭环留给关键事实。

    策略 1 · 最通用

    RAG 接地

    检索相关文档，把“只使用参考文档、没有就说无法回答、引用具体段落”写进 prompt。原文口径可减少 35–60% 幻觉，但不能消除：模型仍可能忽略文档或错误解读。

    策略 2 · 最可靠

    Guardian Agent 验证

    独立 Agent 抽取声明，逐条搜索证据并验证；有未验证声明就修正回答。原文口径可把幻觉率降到 1% 以下，代价是 2–5 秒额外延迟和高成本。

    策略 3 · 最便宜

    结构化输出约束

    用固定 schema 要求 answer、sources、confidence、caveats。它压缩自由生成空间，原文口径减少 20–30%，但不能保证内容真实。

    策略 4 · Agent 专用

    工具输出验证

    把工具原始数据和 Agent 总结一起交给 verifier，检查是否有遗漏、歪曲或添加。这是针对“工具返回对、总结写错”的唯一直接手段。

    RAG 接地的 prompt 结构

    原文示例（仅展示，不执行）

    基于以下参考文档回答问题。
规则：
- 只使用参考文档中的信息
- 如果文档中没有相关信息，明确说"根据现有资料无法回答"
- 引用具体的文档段落作为依据

参考文档：{docs}
问题：{question}

    这三条规则分别对应三种失败：不用文档就自由发挥、不知道却硬答、答了但无法追溯。生产上还要加 Faithfulness 评估（例如 Ragas 的 Faithfulness 指标），否则“看起来引用了”不等于“引用支持结论”。

    结构化输出约束的 schema

    原文示例（Python，仅展示，不执行）

    from pydantic import BaseModel

class FactualAnswer(BaseModel):
    answer: str
    sources: list[str]     # 必须列出来源
    confidence: float      # 自评置信度
    caveats: list[str]     # 注意事项 / 不确定之处

    schema 本身不判别真伪，它的价值是强制模型暴露来源和不确定之处，让后续验证有抓手。自评置信度也不能直接当事实，校准差的模型会“自信地编”。

    工具输出验证：一个具体例子

    工具返回原始数据“2025 Q3 营收 1,200 万元”，Agent 总结成“Q3 营收同比增长 20%”。增长率不在原始数据里，属于 Agent 自己加的。验证 prompt 要问三件事：总结是否准确反映原始数据、是否遗漏、是否添加了原文没有的信息。输出可以是 {"accurate": false, "issues": [...]}。

    这一步不能省。RAG 管的是“回答前有没有依据”，工具输出验证管的是“读完依据后有没有歪曲”。两者覆盖的是不同阶段。

    不要把减少率相加

    “RAG 减少 50% + Guardian 减少 90%”不等于 140%，也不等于“叠加后一定更好”。不同策略作用于不同失败模式，效果会重叠，成本也会叠加。正确做法是按场景风险选组合，再用自己的评测集测。

    按风险分级分配检测预算

    按场景风险级别分配幻觉检测预算
    层级适用输出组合取舍
    第 1 层 · 全部输出所有面向用户的回答结构化约束 + 低温度几乎免费；只能减少自由发挥，不能保证事实。
    第 2 层 · 重要场景业务数据、文档问答第 1 层 + RAG 接地低成本；需要检索质量与 Faithfulness 评估。
    第 3 层 · 关键决策财务、医疗、对外承诺第 2 层 + Guardian Agent + 人工确认高成本、高延迟；换来可追溯的逐条证据。

    原文的四条追问都指向同一个结论：幻觉不能被“完全消除”，只能按风险分层压低。对 Agent 来说，关键场景还要加一道“执行前确认”，因为错误一旦变成工具调用，就不再是文本问题。

    常见误区 / 面试追问

    两个误区，
    两个追问。

    按原文顺序保留 4 条：前两条是误区，后两条是追问。

    误区 1

    “用 RAG 就能消除幻觉。”

    RAG 显著减少幻觉，但不能消除。模型仍可能忽略检索到的文档自由发挥，或错误解读文档内容。RAG 要配合输出验证和 Faithfulness 评估（如 Ragas 的 Faithfulness 指标），否则“有引用”不等于“引用支持结论”。

    误区 2

    “Agent 调了工具就不会幻觉。”

    Agent 在解读工具输出时仍会引入幻觉。数据库返回“Q3 收入 1,200 万”，Agent 可能总结成“Q3 收入增长 20%”，增长率是它自己编的。需要对工具输出的解读做专门验证。

    追问 1

    “如何在成本和幻觉检测率之间取平衡？”

    分级策略：所有输出用结构化约束 + 低温度，几乎免费；重要场景加 RAG 接地，成本低；关键决策用 Guardian Agent 验证，成本高但最可靠。按场景风险级别分配检测预算，不要对所有输出用同一套最贵的检测。

    追问 2

    “幻觉能被完全消除吗？”

    从当前技术看不能。幻觉是 LLM 基于概率采样、而非事实检索的生成机制的固有特性。但多层缓解可以把关键场景的幻觉率压到极低水平（原文口径 < 1%）。长期方向是 Guardian Agent 架构加神经符号混合方法。
