为什么不一样

普通代码跑一次，
Agent 代码跑一圈。

普通函数是确定性、单次执行；Agent 是非确定性、多步循环、带外部副作用。循环里的每一步都可能放大成本和风险。

三个“严重”为什么严重

循环保护缺失，一次模型幻觉可能把 Token 账单放大几百倍；工具无超时，一个外部 API 卡住会阻塞整个进程，连带影响其他用户；敏感操作无确认，删文件和执行 SQL 都是不可逆的，模型一次误判就可能造成数据损失。

三个“中等”不是不重要，而是它们更容易在事故后被补救：错误处理影响的是模型能否正确决策，Prompt 硬编码影响的是可复现和可回滚，可观测性影响的是事后能不能查。它们共同决定下一次故障的排查速度。

逐项要点

每条修复，
都要回答一个风险。

下面六条按原文的顺序整理。修复代码是原文片段，本页只展示，不执行。

1. 循环保护

while True 没有退出条件。模型若反复生成 tool_calls 而不返回最终回答，Agent 会无限循环消耗 Token。修复是用 for step in range(max_steps)，循环结束仍没完成就抛 AgentLoopLimitError。

2. 工具超时

requests.get 默认没有超时。外部 API 无响应时会一直等，阻塞整个进程。修复是换 httpx 并显式设置 timeout=10.0。

3. 结构化错误处理

except Exception 加 print 有三个缺陷：吞掉所有异常（包括 MemoryError）；print 无法被监控系统捕获；LLM 只收到模糊的 Error 字符串，无法判断该重试还是放弃。修复是分层捕获 KeyError、TimeoutError 和兜底异常，用 logging 记录，并返回结构化 JSON。

4. Prompt 版本管理

System prompt 直接写在 __init__ 里，无法 A/B 测试、无法版本管理、无法热更新；其中“如果不确定，就多试几次”还会直接鼓励盲目重试。修复是 PromptRegistry 从外部 YAML 加载，并按版本取用。

5. 可观测性

原文代码零 logging、零 tracing、零 metrics。生产出问题时无法回溯 Agent 走了几步、调用了哪些工具、每步耗时和 Token 消耗。修复是生成 trace_id，每一步记录耗时、输入输出 token 和工具名。

6. 敏感操作确认

delete_file、execute_sql 直接执行，模型幻觉或 prompt injection 都可能造成不可逆破坏。修复是把敏感工具放进 SENSITIVE_TOOLS，执行前请求人工确认；拒绝就返回结构化错误，而不是继续执行。

Checklist

SECURE 六条，
每次 PR 过一遍。

单元测试分三层

原文建议：第一层工具函数单测，Mock 外部依赖，验证正常、超时、异常；第二层 Agent 循环单测，Mock LLM 返回固定的 tool_calls 序列，验证 max_steps 触发和敏感工具拦截；第三层集成 Eval，真实 LLM 加沙箱环境验证端到端完成率。

关键原则是不要断言 LLM 的具体输出，而是断言 Agent 的行为属性：是否限步完成、是否拦截危险操作、是否生成完整 trace。具体输出会随模型变化，行为属性才是可回归的。

常见误区 / 面试追问

两个误区，
两个追问。

Agent 代码不能套用普通 Review 标准；加了 try-catch 也不等于处理了错误。Checklist 和单元测试是常见追问。

误区 01

“Agent 代码和普通代码的 Review 标准一样”

Agent 代码的核心特征是非确定性循环加外部副作用。普通 Review 关注逻辑正确性和代码风格，Agent 代码还必须审查循环边界、成本控制、权限隔离、可观测性等维度。忽略这些维度的 Review 等于没有 Review，建议维护专门的 Agent Code Review Checklist。

误区 02

“加了 try-catch 就算处理了错误”

except Exception 配 print 是最危险的“伪处理”。生产级错误处理需要分层捕获（区分可重试与致命错误）、结构化返回（让 LLM 根据错误类型决策）、持久化记录（logging 而非 print）。Agent 的错误信息会反馈给 LLM，格式化 JSON 远比 “Error: something went wrong” 有用。

追问 03

如何设计 Agent 代码审查 Checklist？

按 SECURE 助记法组织：Steps Limit、Error Handling、Cost Guard、User Confirmation、Replay & Trace、External Timeout。每次 PR Review 逐条过一遍，系统性覆盖六个维度。

追问 04

如何为 Agent 编写单元测试？

分三层：工具函数单测（Mock 外部依赖，验证正常、超时、异常）；Agent 循环单测（Mock LLM 返回固定 tool_calls 序列，验证 max_steps 和敏感工具拦截）；集成 Eval（真实 LLM + 沙箱，验证端到端完成率）。不断言具体输出，只断言行为属性。
