高级 · Prompt Engineering · 可交互讲解

同一句话，
四个模型四种反应。

Prompt 高度模型特异：分词、指令风格、格式偏好、CoT 行为和安全边界都不同。可移植的做法是拆成两层：模型无关的核心 Prompt + 每个模型一个薄适配层。

关键边界：换 API endpoint 不等于迁移完成。格式、参数和安全边界都要重新验证；原文提到，为某个模型优化的 Prompt 迁移到另一个模型，性能平均下降 10–30%。

为什么不可移植

四类差异，
不只在 API 格式。

原文列出的差异包括格式偏好、指令理解、CoT 行为和安全边界；分词方式不同还会改变同样文本的 token 数和截断位置。

格式偏好

原文描述：GPT-4 偏好 JSON 工具参数，Claude 偏好 XML 标签分隔结构，Gemini 对 Markdown 结构响应最好，Llama 对简洁直接指令响应最好。

指令理解

同一句“简洁回答”，原文示例：GPT-4 输出 2–3 句话，Claude 输出 1 段话，Llama 可能输出 1 个词。

CoT 行为

有的模型自带思考，有的需要显式提示。原文示例：o1/o3 自动思考，GPT-4 需要 “Let's think step by step”。

安全边界

不同模型的安全过滤阈值不同：Claude 拒绝的请求 GPT-4 可能回答，反之亦然。迁移后必须重跑安全测试。

还有两类差异不在格式里：分词方式不同，同样文本的 token 数不同，长 Prompt 可能在一个模型里被截断、在另一个里不会；能力边界不同，上下文长度、多语言和推理能力都会影响同一 Prompt 的表现。

这些偏好是原文给出的经验描述，不是永久定律。实际迁移前要用目标模型跑评测；格式偏好会随模型版本和原生 tool use 能力变化，不能当成硬编码规则。

设计原则

说清楚要什么，
别依赖魔法短语。

模型无关的 Prompt 用清晰自然语言写，把所有期望显式化，用通用分隔符，避免依赖某个模型的特有能力或最大上下文。

原则不要改成
清晰自然语言Let's think step by step（只对特定模型有效）“请分步骤分析这个问题，每步列出推理过程”
显式化期望“回答这个问题”（格式和长度靠模型猜）“用 2–3 句话回答，使用中文，不加标题”
结构化分隔<thinking> 标签（Claude 特有）--- 分隔线、Markdown 标题、编号列表
避免极端依赖依赖最大上下文长度或某个模型独有能力Prompt 长度控制在 2000 token 以内（所有模型都支持）

“显式化”不是把 Prompt 写成操作手册。它指的是：输出格式、长度、语言、禁止项都写出来，不假设模型会自己选对默认值。

适配层架构

核心一份，
适配器每个模型一份。

核心 Prompt 只写任务、规则和风格；适配器负责 wrapper、system role 和 temperature。新增模型只加一个适配器，不改核心。

class PromptAdapter:
    def __init__(self):
        self.core_prompts = {
            "customer_service": """
            你是客服助手。
            职责：回答产品问题、处理退款、查询订单。
            规则：
            1. 使用友好专业的语言
            2. 不确定时建议联系人工
            3. 退款超过 500 元转人工

            用户消息：{user_input}
            """,
        }
        self.model_adapters = {
            "gpt-4": {
                "wrapper": '以 JSON 格式输出你的回复：\n{"response": "...", "action": "..."}\n',
                "system_role": "system",
                "temperature": 0.7,
            },
            "claude": {
                "wrapper": "请在 <response> 标签中输出回复，在 <action> 标签中输出操作。\n",
                "system_role": "system",
                "temperature": 0.7,
            },
            "llama": {
                "wrapper": "回复格式：\n回复：...\n操作：...\n",
                "system_role": "system",
                "temperature": 0.6,
            },
        }

    def get_prompt(self, prompt_id, model, **kwargs):
        core = self.core_prompts[prompt_id]
        adapter = self.model_adapters.get(model, self.model_adapters["gpt-4"])
        full_prompt = core.format(**kwargs) + "\n" + adapter["wrapper"]
        return full_prompt, adapter

PromptBridge

自动迁移，
也要验证集兜底。

原文介绍 PromptBridge（arXiv:2512.01420，2025）：用反思式 Prompt 演化做跨模型适配，训练自由，不需要微调源模型或目标模型。

class PromptBridge:
    async def migrate(self, prompt, source_model, target_model, eval_set):
        # Step 1: 分析源 Prompt 的意图和结构
        analysis = await self.analyze_prompt(prompt, source_model)

        # Step 2: 生成目标模型的候选适配
        candidates = await self.generate_adaptations(
            prompt=prompt,
            analysis=analysis,
            target_model=target_model,
            k=5,
        )

        # Step 3: 在验证集上评估，选最高分
        best_candidate = None
        best_score = 0
        for candidate in candidates:
            score = await self.evaluate(candidate, target_model, eval_set)
            if score > best_score:
                best_score = score
                best_candidate = candidate
        return best_candidate

    async def analyze_prompt(self, prompt, model):
        return await self.analyzer_llm.invoke(f"""
        分析以下针对 {model} 的 Prompt：
        {prompt}
        提取：核心任务意图、输出格式要求、约束和规则、
        模型特定技巧、可以通用化的部分。
        """)

迁移清单

格式、指令、参数、
验证，四组都要过。

迁移不是改一个 wrapper 就结束。原文把工作分成四组：格式迁移、指令迁移、参数迁移、验证。

类别要做什么
格式迁移JSON ↔ XML ↔ Markdown 转换；特定标签替换（<thinking> → 通用的“推理过程”）；函数调用格式适配。
指令迁移调整详细程度；添加或移除 CoT 提示；调整 Few-shot 示例的数量和格式。
参数迁移Temperature 调整；Max tokens 适配；Stop sequences 更新。
验证在标准测试集上对比新旧模型；检查极长输入、特殊字符、多语言；做安全测试，确认注入防御仍然有效。

多模型 Agent

规划用强模型，
执行用快模型。

多模型系统按阶段分配模型：规划、执行、评估可以用不同模型，每个阶段通过适配层拿到对应的 Prompt 和参数。

class MultiModelAgent:
    def __init__(self):
        self.models = {
            "planning": "claude-opus-4-5",       # 规划用强模型
            "execution": "gpt-4o-mini",          # 执行用快模型
            "evaluation": "claude-sonnet-4-5",   # 评估用中等模型
        }
        self.adapter = PromptAdapter()

    async def run(self, task):
        plan_prompt = self.adapter.get_prompt(
            "planning", model=self.models["planning"], task=task
        )
        plan = await self.call(self.models["planning"], plan_prompt)

        exec_prompt = self.adapter.get_prompt(
            "execution", model=self.models["execution"], plan=plan
        )
        result = await self.call(self.models["execution"], exec_prompt)
        return result

常见误区 / 面试追问

两个误区，
两个追问。

两条误区都在低估迁移成本；两条追问问企业为什么要多模型，以及怎么低成本接新模型。

误区 1

“好的 Prompt 在所有模型上都好用。”

原文给出的数据是：为一个模型优化的 Prompt 迁移到另一个模型时，性能平均下降 10–30%。尤其是利用了模型特定行为的 Prompt（如 Claude 的 XML 标签、GPT 的 JSON mode），迁移后几乎必然失效。

误区 2

“只需要换 API endpoint 就能切换模型。”

API 格式只是表层差异。深层差异包括模型对指令的理解方式、默认行为、安全边界和推理风格。真正的模型切换需要 Prompt 适配 + 验证测试。

追问 1

为什么企业需要多模型支持？

三个原因：避免供应商锁定，单一供应商 API 中断会导致业务停滞；成本优化，不同任务用不同价位的模型；性能优化，某些任务在特定模型上效果更好。

追问 2

如何在不手动迁移的情况下支持新模型？

核心 Prompt + 适配层架构。核心 Prompt 用模型无关的自然语言编写，适配层处理格式和参数差异；新模型只需添加新的适配层。PromptBridge 等工具可以自动化这个过程，但仍要用验证集评估。
