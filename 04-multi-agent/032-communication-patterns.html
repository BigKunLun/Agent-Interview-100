基础 · Multi-Agent · 可交互讲解

三个 Agent，
怎么把话传对。

多 Agent 之间交换信息有三种基本做法：消息传递像互相发快递，共享状态像共用一块白板，黑板模式像围着公告栏协作。三种做法解决的是“信息怎么流动”，不是“谁来指挥”。

关键边界：通信模式与编排模式是正交维度。同一条 Pipeline，既可以用消息传递实现，也可以用共享状态实现；选通信模式时，先看信息是定向送达还是全局共享。

模式 1

消息传递：
定向投递，像发快递。

Agent 之间直接发结构化消息，可以点对点，也可以广播。它适合动态、针对性的信息共享，代价是路由逻辑和全局一致性都要自己管。

一条消息至少有五个字段：发送者、接收者、消息类型、数据负载和时间戳。生产环境通常把消息放进消息队列（如 RabbitMQ、Redis Streams），由队列保证异步送达和重试。

点对点与广播 · 原文代码

class MessageBus:
    def __init__(self):
        self.queues = {}  # agent_id → message_queue

    async def send(self, from_agent: str, to_agent: str, message: dict):
        """发送消息给特定 Agent"""
        msg = {
            "from": from_agent,
            "to": to_agent,
            "content": message,
            "timestamp": datetime.now()
        }
        await self.queues[to_agent].put(msg)

    async def broadcast(self, from_agent: str, message: dict):
        """广播消息给所有 Agent"""
        for agent_id, queue in self.queues.items():
            if agent_id != from_agent:
                await queue.put({"from": from_agent, "content": message})

bus = MessageBus()
await bus.send("researcher", "writer",
    {"type": "research_complete", "data": findings})

优势：针对性强、延迟低、Agent 之间解耦。劣势：容易形成信息孤岛，路由逻辑复杂，难以保证全局一致。

容易混淆的地方

这里的“消息”不是自然语言聊天，而是带类型和字段的结构化数据。接收方按类型分支处理，不靠猜语气。

模式 2

共享状态：
所有人读写同一份文档。

所有 Agent 围绕一个状态存储读写，类似多人编辑同一份文档。好处是人人看到同一份全局视图，坏处是并发写要加锁，存储也可能成为瓶颈。

并发控制 · 原文代码

import asyncio

class SafeSharedState:
    def __init__(self):
        self.state = {}
        self.lock = asyncio.Lock()

    async def update(self, agent_id: str, updates: dict):
        async with self.lock:  # 确保原子更新
            self.state.update(updates)
            self.state["last_updated_by"] = agent_id

共享状态的“共享”是数据层面的共享，不是消息层面的转发。Agent 不互相寄信，而是各自读写同一个键值空间；某一步读到什么，取决于上一步有没有写入。

模式 3

黑板模式：
公共公告栏，各自贡献。

经典 AI 架构模式：任务写在黑板上，控制器决定下一个谁行动，Agent 读取公共区、按专长处理、再把结果写回黑板，循环到问题解决。

黑板与控制器 · 原文代码

class Blackboard:
    def __init__(self):
        self.public_space = []    # 公共区域：所有 Agent 可见
        self.private_spaces = {}  # 私有区域：各 Agent 独立空间

    def post(self, agent_id: str, content: dict, visibility="public"):
        entry = {
            "author": agent_id,
            "content": content,
            "timestamp": datetime.now()
        }
        if visibility == "public":
            self.public_space.append(entry)
        else:
            self.private_spaces.setdefault(agent_id, []).append(entry)

    def read(self, agent_id: str) -> list:
        return self.public_space + self.private_spaces.get(agent_id, [])

class BlackboardSystem:
    def __init__(self, blackboard, agents, controller):
        self.blackboard = blackboard
        self.agents = agents          # 专家 Agent 列表
        self.controller = controller  # 控制器（决定谁行动）

    async def run(self, task):
        self.blackboard.post("system", {"task": task})
        while not self.is_solved():
            active_agent = self.controller.select(
                self.blackboard, self.agents
            )
            result = await active_agent.process(
                self.blackboard.read(active_agent.id)
            )
            self.blackboard.post(active_agent.id, result)

黑板模式的关键特性是四点：自愿参与（Agent 按专长决定是否响应）、迭代精化（多轮读写逐步完善）、去中心化（控制器不必预先知道所有能力）、Token 高效（共享公共记忆，减少重复传递）。

任务发布上黑板→ 控制器选择 Agent→ 读取黑板→ 处理 · 贡献专长→ 写回黑板→ 问题解决？

否 → 回到“控制器选择 Agent”，继续下一轮
是 → 输出最终方案

研究结果（原文引用，未联网核实）：原文称黑板架构在端到端任务成功率上比 RAG 和 Master-Slave 模式提升 13%–57%。这是原文引用的研究结论，不是本页的实测数据。

实际选择指南

按场景选模式 · 原文代码

def choose_pattern(scenario):
    if scenario == "少量 Agent + 简单流程":
        return "共享状态（LangGraph State）"
    elif scenario == "Agent 数量多 + 动态组合":
        return "黑板模式"
    elif scenario == "异步处理 + 微服务架构":
        return "消息传递（消息队列）"
    elif scenario == "需要最大灵活性":
        return "混合模式（消息传递 + 共享状态）"

这张决策表是原文给出的经验规则，不是硬性判据。真实系统里常见的做法是混合：用共享状态保存全局事实，用消息传递处理异步通知。

常见误区 / 面试追问

四个容易
答偏的点。

前两条是误区，后两条是面试追问；答案来自原文。

误区 1

“消息传递就是聊天。”

多 Agent 通信中的消息传递是结构化的、带类型的数据交换，不是自然语言对话。消息应包含类型、发送者、接收者、数据负载和时间戳。接收方按类型处理，不靠理解聊天语气。

误区 2

“共享状态很简单，用全局变量就行。”

生产环境中的共享状态需要锁机制、版本控制和持久化。多个 Agent 并发读写同一状态时，必须防止竞态条件；全局变量既不持久，也不处理并发。

追问 1

黑板模式和共享状态有什么本质区别？

共享状态是被动的数据存储，Agent 按预定流程读写；黑板模式是主动的协作平台，Agent 自主观察黑板内容并决定是否参与。黑板有控制器决定执行顺序，Agent 有自愿参与的机制。

追问 2

如何处理 Agent 间的信息冗余？

原文引用研究称 token 冗余率可达 53%–86%（原文数据，未联网核实）。常见做法是消息摘要（传摘要而非原文）、用黑板公共记忆替代个体记忆、以及去重机制。
