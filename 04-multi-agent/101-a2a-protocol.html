中级 · Multi-Agent · 可交互讲解

Agent 之间，
也要说同一种语言。

A2A（Agent-to-Agent）是 Google 在 2025 年 4 月发布的开放协议，目标是让不同厂商、不同框架构建的 Agent 直接通信与协作。它基于 HTTP + JSON-RPC 2.0 + SSE，用 Agent Card 发现能力，用 Task 管理有状态的任务生命周期。

关键边界：A2A 管 Agent 与 Agent 之间的横向协作，MCP 管 Agent 与工具、数据源之间的纵向连接。两者互补，不互相替代。

Agent 越多，
孤岛越明显。

核心概念

Agent Card 负责发现，
Task 负责过程。

Agent Card 声明“我会什么”，Task 记录“这件事做到哪了”，Message 承载对话，Artifact 承载产物。四者分工明确，才能让不透明的 Agent 之间协作。

1. Agent Card（服务发现）

每个 A2A Agent 在 /.well-known/agent-card.json 发布 Agent Card，声明能力和认证方式，作用类似 OpenAPI spec。早期版本使用 /.well-known/agent.json，后改为 agent-card.json 以符合 RFC 8615。原文还提到协议新增了 gRPC binding 与 Agent Card signing 支持；具体版本以 A2A 协议仓库最新版本为准。

2. Task 生命周期

A2A Task 状态与允许的迁移
状态含义可迁移到
submitted已提交，尚未开始执行working / failed
working正在执行completed / failed / input-required
input-required缺少必要输入，任务暂停working（补充后恢复）/ failed
completed成功结束终态
failed失败结束终态

Task 是有状态的工作单元：可以暂停等待输入，再恢复执行，而不是一次无状态的调用。原文用 Mermaid 的 stateDiagram-v2 描述这套状态机，源码保留在下方。

3. Message 和 Artifact

Message 是 Agent 间的对话载体，可以包含 text、file 等多模态 parts。Artifact 是任务产出的结构化成果物，和 Message 分开存放，便于下游直接消费。

A2A vs MCP

一个连工具，
一个连同伴。

MCP 让 Agent 变得更强，A2A 让 Agent 之间能合作。两者解决正交问题，一个成熟系统往往同时使用。

示例的关键不在 HTTP 细节，而在三件事：Agent Card 声明能力、Task 状态迁移受合法转换表约束、缺少输入时暂停而不是失败。

展开原文 Python 示例 
import json
import uuid
from dataclasses import dataclass, field
from enum import Enum


class TaskState(Enum):
    """A2A Task 状态枚举"""
    SUBMITTED = "submitted"
    WORKING = "working"
    INPUT_REQUIRED = "input-required"
    COMPLETED = "completed"
    FAILED = "failed"


@dataclass
class AgentCard:
    """Agent Card —— 声明 Agent 的能力，发布于 /.well-known/agent-card.json"""
    name: str
    description: str
    url: str
    skills: list[dict] = field(default_factory=list)
    capabilities: dict = field(default_factory=lambda: {
        "streaming": True, "pushNotifications": False,
    })


@dataclass
class Task:
    """A2A Task —— 协议核心工作单元，带状态机校验"""
    id: str = field(default_factory=lambda: str(uuid.uuid4()))
    state: TaskState = TaskState.SUBMITTED
    messages: list[dict] = field(default_factory=list)
    artifacts: list[dict] = field(default_factory=list)

    _transitions = {
        TaskState.SUBMITTED: {TaskState.WORKING, TaskState.FAILED},
        TaskState.WORKING: {TaskState.COMPLETED, TaskState.FAILED,
                            TaskState.INPUT_REQUIRED},
        TaskState.INPUT_REQUIRED: {TaskState.WORKING, TaskState.FAILED},
    }

    def transition(self, new_state: TaskState):
        allowed = self._transitions.get(self.state, set())
        if new_state not in allowed:
            raise ValueError(
                f"非法状态转换: {self.state.value} -> {new_state.value}")
        self.state = new_state


class A2AServer:
    """模拟 A2A 服务端 —— 接收 JSON-RPC 请求、管理 Task 生命周期"""

    def __init__(self, card: AgentCard):
        self.card = card
        self.tasks: dict[str, Task] = {}

    def handle_request(self, request: dict) -> dict:
        method = request["method"]
        params = request.get("params", {})
        req_id = request["id"]

        if method == "message/send":
            result = self._send(params)
        elif method == "tasks/get":
            task = self.tasks[params["id"]]
            result = {"id": task.id, "state": task.state.value}
        else:
            return {"jsonrpc": "2.0", "id": req_id,
                    "error": {"code": -32601, "message": "方法不存在"}}

        return {"jsonrpc": "2.0", "id": req_id, "result": result}

    def _send(self, params: dict) -> dict:
        task_id = params.get("id", str(uuid.uuid4()))
        if task_id in self.tasks:
            task = self.tasks[task_id]
            task.messages.append(params["message"])
            task.transition(TaskState.WORKING)  # 从 input-required 恢复
        else:
            task = Task(id=task_id, messages=[params["message"]])
            self.tasks[task_id] = task
            task.transition(TaskState.WORKING)

        text = task.messages[-1]["parts"][0]["text"]
        if "分析" in text and "时间" not in text:
            task.transition(TaskState.INPUT_REQUIRED)
            return {"id": task.id, "state": task.state.value,
                    "messages": [{"role": "agent",
                                  "parts": [{"type": "text",
                                             "text": "请指定分析时间范围"}]}]}

        task.transition(TaskState.COMPLETED)
        task.artifacts.append({
            "name": "report",
            "parts": [{"type": "text",
                       "text": f"基于 [{text}] 的分析报告..."}]
        })
        return {"id": task.id, "state": task.state.value,
                "artifacts": task.artifacts}


if __name__ == "__main__":
    server = A2AServer(AgentCard(
        name="财务分析 Agent",
        description="专精于财务报表分析",
        url="https://finance-agent.example.com",
        skills=[{"id": "financial_analysis", "name": "财务报表分析"}],
    ))

    # 第一轮：缺少时间范围
    r1 = server.handle_request({
        "jsonrpc": "2.0", "id": 1, "method": "message/send",
        "params": {"id": "task-001",
                   "message": {"role": "user",
                               "parts": [{"type": "text",
                                          "text": "分析特斯拉营收趋势"}]}}
    })

    # 第二轮：补充时间
    r2 = server.handle_request({
        "jsonrpc": "2.0", "id": 2, "method": "message/send",
        "params": {"id": "task-001",
                   "message": {"role": "user",
                               "parts": [{"type": "text",
                                          "text": "时间范围：2023-2024"}]}}
    })

注意版本差异：核心方法名已从早期的 tasks/send / tasks/sendSubscribe 重命名为 message/send / message/stream。看旧文章时，方法名对不上是常见情况。

设计原则

不透明，
才容得下异构。

A2A 不要求双方用同一个模型、同一个框架，甚至不要求对方暴露内部实现。四条原则都围绕这一点。

A2A 的四条关键设计原则
原则说明
不透明执行客户端不需要了解服务端内部实现，模型和框架都可以不同
框架无关LangChain、CrewAI、AutoGen 等都可以实现 A2A
能力协商通过 Agent Card 动态发现并选择合适的 Agent
安全优先内置企业级认证授权：OAuth 2.0、API Key、mTLS

长时间运行的任务由三种机制覆盖：message/stream 用 SSE 推送中间状态；Push Notification 让客户端注册 webhook，服务端在状态变更时主动通知；tasks/get 轮询随时查进度。三种机制覆盖秒级到天级的任务时长。

常见误区 / 面试追问

四个容易
答偏的问题。

前两个是误区，后两个是追问。回答时先讲定位，再讲机制。

误区 01

“A2A 会取代 MCP”

A2A 和 MCP 解决的是两个正交问题。MCP 是 Agent 连接工具和数据源的标准，属于纵向扩展能力；A2A 是 Agent 之间协作通信的标准，属于横向建立合作。成熟系统往往同时需要两者：用 MCP 获取能力，用 A2A 分工协作。它们更像 TCP 和 HTTP 的关系，不同层次、互相配合。原文称 2026 年这一双层标准定位已成行业共识。

误区 02

“A2A 只适用于同构 Agent”

恰恰相反，A2A 的核心设计目标就是让异构 Agent 互通。无论 Agent 基于 Claude、GPT 还是 Gemini，用 LangChain 还是自研框架，只要实现 A2A 协议就能互相协作。Agent Card 里的 skills 是语义级描述，不是实现级绑定。

追问 03

A2A 如何处理长时间运行的任务？

三种机制：message/stream 用 SSE 实时推送中间状态和增量结果；Push Notification 通过 webhook 回调，适合数小时级任务；tasks/get 随时轮询进度。三者覆盖秒级到天级。

追问 04

如何在 A2A 中实现身份验证和授权？

Agent Card 的 authentication 字段声明支持的认证方案。协议复用成熟的 Web 安全标准：OAuth 2.0（企业间协作首选）、API Key（内部系统）、JWT Bearer Token（无状态场景）。Agent Card 的 skills 还可以设置权限级别，实现细粒度能力授权，例如允许“查询”但禁止“修改”。
