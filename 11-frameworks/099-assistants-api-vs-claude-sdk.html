    一、先分清三层

    Assistants、Responses、
    Agents SDK 不是一回事。

    原文特意纠偏：Assistants API 是 2023 年的云端有状态 API；Responses API 才是它的直接替代者；Agents SDK 是 Responses API 上层的轻量编排框架。三者是分层关系，不是改名关系。

    API 层 · 2023 Assistants API Thread / Message / Run 模型，云端托管有状态 2025-08-26 公告 deprecated
    API 层直接替代→
    API 层 · 2025-03 Responses API 同样云端管理状态，API 设计更现代 Assistants 的直接替代者
    SDK 层编排→
    SDK 层 · 2025-03 OpenAI Agents SDK Agent / Handoff / Guardrails，基于 Responses API 轻量编排

    另一条路线：Anthropic Claude Agent SDK（2025-09 从 claude-code-sdk 重命名而来，与 Claude Sonnet 4.5 同步发布）不在上面这条 OpenAI 分层链里。它基于 Claude Code 的实战经验构建，底层是 Messages API + MCP。

    “Agents SDK 是 Assistants API 的直接替代者”这句话是错的。直接替代发生在 API 层：Assistants → Responses。Agents SDK 是 SDK 层的编排框架，它建立在 Responses API 之上。

    三、OpenAI Agents SDK

    三个概念，
    把编排压到最小。

    Agent 是带指令和工具的 LLM，Handoff 是 Agent 间任务交接，Guardrails 是输入/输出验证。SDK 内置追踪、类型安全和 Agent Loop，但不强制托管状态。

    OpenAI Agents SDK · 原文代码，仅转义展示，不执行

    # OpenAI Agents SDK：最小抽象，三个核心概念
from agents import Agent, Runner, handoff, GuardrailFunctionOutput
from agents import input_guardrail

# 核心概念 1：Agent — 带指令和工具的 LLM
triage_agent = Agent(
    name="Triage Agent",
    instructions="根据用户问题类型，转接到合适的专家。",
    handoffs=[sales_agent, support_agent],  # 可以交接给谁
)

sales_agent = Agent(
    name="Sales Agent",
    instructions="处理销售相关问题。",
    tools=[lookup_pricing, create_quote],
)

support_agent = Agent(
    name="Support Agent",
    instructions="处理技术支持问题。",
    tools=[search_kb, create_ticket],
)

# 核心概念 2：Handoff — Agent 间的任务交接
# LLM 自动决定何时交接，交接时携带上下文

# 核心概念 3：Guardrails — 输入/输出安全检查
@input_guardrail
async def check_injection(ctx, agent, input):
    """检查 Prompt 注入"""
    result = await Runner.run(
        injection_detector,
        input,
        context=ctx.context,
    )
    return GuardrailFunctionOutput(
        output_info=result,
        tripwire_triggered=result.is_injection,
    )

# 运行 Agent
result = await Runner.run(triage_agent, "我想了解企业版定价")

# Agents SDK 特点：
# 1. 极简 API——三个概念覆盖大部分场景
# 2. 内置追踪——自动记录每步执行
# 3. 类型安全——Pydantic 模型验证输出
# 4. Agent Loop 内置——自动处理工具调用循环

    状态在云侧：Responses API 负责云端状态托管，Agents SDK 在其上做编排。好处是省心，代价是更强的平台锁定：应用代码更薄，原本可以自己换掉的编排逻辑也逐步变成平台能力。

    四、Claude Agent SDK

    工具优先，
    把 MCP 接进运行时。

    核心 API 是 ClaudeAgentOptions + 异步 query()。MCP 服务器配置即工具发现；Permission Mode 和 Hooks 提供细粒度的授权与拦截；Subagent 通过 Task 工具在运行时派生，不是静态声明列表。

    Claude Agent SDK · 原文代码，仅转义展示，不执行

    # Claude Agent SDK（pip install claude-agent-sdk，2025-09 从 claude-code-sdk 重命名）
# 核心 API：ClaudeAgentOptions + 异步 query() 函数
# 详见：https://docs.anthropic.com/en/api/agent-sdk

import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions

# 1. 最简用法：直接 query()
async def simple_example():
    options = ClaudeAgentOptions(
        model="claude-sonnet-5",
        system_prompt="你是一个数据分析助手。",
    )
    async for msg in query(prompt="分析 sales.csv 并给出 Top 3 趋势", options=options):
        print(msg)

# 2. 配置 MCP 工具服务器（真实 dict 结构，非 URL 列表）
options = ClaudeAgentOptions(
    model="claude-sonnet-5",
    mcp_servers={
        # stdio 子进程式（最常见）
        "filesystem": {
            "type": "stdio",
            "command": "npx",
            "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"],
        },
        # HTTP 远程
        "github": {
            "type": "http",
            "url": "https://mcp.github.com/v1",
            "headers": {"Authorization": "Bearer $GITHUB_TOKEN"},
        },
    },
    # 允许哪些工具，可精确到工具名
    allowed_tools=["Read", "Write", "Bash", "mcp__filesystem__read_file"],
)

# 3. Permission Mode（细粒度授权控制——这是真正的 HITL 机制）
options = ClaudeAgentOptions(
    model="claude-sonnet-5",
    permission_mode="acceptEdits",  # 自动接受文件编辑
    # 可选值: "default" | "acceptEdits" | "bypassPermissions" | "plan"
    # plan 模式下 Agent 只规划不执行，必须人工 confirm 后才能 run
)

# 4. Hooks 机制：在工具调用前后注入逻辑（这是真实可观测/HITL 的方式）
async def pre_tool_hook(tool_name: str, tool_input: dict):
    if tool_name == "Bash" and "rm" in tool_input.get("command", ""):
        return {"deny": True, "reason": "Dangerous command blocked"}
    return {"deny": False}

options = ClaudeAgentOptions(
    model="claude-sonnet-5",
    hooks={"PreToolUse": pre_tool_hook},
)

# 5. Subagent 模式（多 Agent 编排）：通过 Task 工具派生子 Agent
# Claude SDK 没有静态的"sub_agents 列表"参数，而是运行时由主 Agent 决定派生
# 主 Agent 调用 Task 工具时，会启动一个独立上下文的子 Claude 实例
options = ClaudeAgentOptions(
    model="claude-sonnet-5",
    system_prompt="你是项目经理，可通过 Task 工具委派 researcher/coder/reviewer 子 Agent",
    allowed_tools=["Task", "Read", "Write"],
)

# Claude SDK 真实特性：
# 1. MCP 原生集成——配置即工具发现
# 2. Permission Mode + Hooks——细粒度的 HITL 和安全护栏
# 3. Subagent via Task 工具——主 Agent 运行时派生子 Agent，非静态声明
# 4. 文件系统检查点——基于 .claude/ 目录的状态持久化

    原文提醒：Claude SDK 没有静态的 sub_agents 列表参数，Subagent 是运行时由主 Agent 通过 Task 工具派生的。另一个容易忽略的点是，Permission Mode 和 Hooks 才是它真正的 HITL 机制，而不是另建一套审批 API。

    方向含义云端承担更多 Agent 运行时职责，平台锁定进一步加深依赖开放协议的官方实现，减少自研代码、提升互操作保真度

    OpenAI：编排从 SDK 层下沉到 API 层

    The builder's guide to GPT-5.6（2026-08-13）的核心建议是不默认用旗舰、按任务下沉到更省的小模型（Luna / Terra，配套定价显示 Luna 降价约 80%），并推介 Responses API 三项新能力：保留推理态（跨轮次保留推理过程，不必每轮重新推理）、原生多 Agent 编排（多 Agent 调度由 API 直接提供，不再必须由应用层 Agents SDK 承担）、程序化工具调用（工具调用由代码逻辑驱动组织，不必每步都走模型决策）。其中“原生多 Agent 编排”进 API 是原文核心论断的直接演进：“SDK 轻 + 云重”进一步向云侧偏移，应用代码更薄，代价是原本可以自己换掉的编排逻辑也变成平台能力，锁定加深。

    Anthropic：MCP 集成从自研分发换成协议原生

    Python SDK v0.2.140（2026-08-18）落地 MCP 2.x：进程内 MCP server 不再手写 JSON-RPC（基于 JSON 的远程调用协议）分发，改走 mcp 官方 in-memory transport。手工构造的 mcp.server.Server 可以原样接入，resources / prompts / 全部 result content type 原样透传，不再被 SDK 中间层削减。意义在保真度和维护成本：把实现让给协议官方，而不是长期维护一份平行实现。

    常见误区 / 面试追问

    四条，
    按原文顺序。

    第一条专门纠正 Assistants API 与 Responses API 的关系；后三条谈绑定、MCP 生态和多模型。

    误区 1

    “Assistants API 和 Agents SDK 是一回事”，或“Agents SDK 是 Assistants API 的直接替代者。”

    实际三者关系是：Assistants API（2023）是云端托管的有状态 API（Thread / Message / Run 模型），OpenAI 于 2025-08-26 公告 deprecated，原文写计划 2026-08-26 关闭（以 OpenAI 官方公告为准；本页未联网核实是否已执行）；Responses API（2025-03）才是 Assistants API 的直接替代者，同样云端管理状态，但 API 设计更现代；Agents SDK（2025-03）是基于 Responses API 的上层轻量级编排框架，提供 Agent / Handoff / Guardrails 抽象。三者是分层关系：Assistants → Responses（API 层替代）→ Agents SDK（SDK 层编排）。

    误区 2

    “选了一个 SDK 就不能用其他模型。”

    OpenAI Agents SDK 的 model_settings 可以配置兼容 OpenAI API 格式的任何提供商。Claude Agent SDK 绑定 Claude，但 MCP 服务器可以被任何客户端使用。关键是区分“SDK 绑定”和“协议绑定”。

    追问 1

    MCP 会成为行业标准吗？

    截至 2026 年初，MCP 已从“Anthropic 提议的标准”成长为事实标准：PulseMCP 收录超 5500 个 MCP Server，约 80% Fortune 500 企业开始参与生态，OpenAI、Google、微软均已宣布支持或兼容 MCP。它解决了“每个 Agent 框架都要自己实现工具集成”的 N×M 问题。但 ACM 2026 学术研究也揭示了开发者痛点：文件系统操作问题占比最高（21.32%），其次是数据验证和类型问题——说明协议走向成熟的同时，工程实践仍在追赶。以上数字按原文 2026 时点保留，未联网核实。

    如果需要同时用 GPT 和 Claude 怎么办？

    推荐架构：使用 LiteLLM 或 Portkey 作为 Model Gateway，统一 API 接口；自研轻量 Agent Loop，不绑定任何特定 SDK；MCP 作为工具层标准，与模型层解耦。核心思想是模型层和工具层分离。
